13:T23ca,<p>The takeaway was we need to figure out AI agent authentication, authorization, delegation, and a lot of other words that end in ion for agents.</p>
<p>More helpfully, here's some of what was mentioned though:</p>
<h1>1. Context and Motivation</h1>
<h2>Why AI Agent Authorization Matters</h2>
<ul>
<li>Rise of multi-agent interactions: AI agents increasingly perform tasks on behalf of humans (e.g., shopping, scheduling, or data retrieval)</li>
<li>Scaling risk: Agents can execute actions at a massive scale, so security and trust become critical</li>
<li>Friction vs. control: We want seamless interactions while ensuring the user remains in control of what each agent can do</li>
</ul>
<h2>Key Problems and Questions</h2>
<ul>
<li>Credential handling: Safely sharing authentication tokens (e.g., cookies, OAuth) with agents</li>
<li>Permissioning: Defining exactly which tasks agents are allowed or not allowed to perform</li>
<li>Chain-of-delegation: Ensuring accountability when tasks (and credentials) are passed among multiple agents</li>
</ul>
<h1>2. Core Concepts and Challenges</h1>
<h2>2.1 Authentication and Authorization</h2>
<ul>
<li>Agent identity: Determining which "user" or "owner" an agent represents</li>
<li>Scoping: Granular permissions, so an agent can only do what a user explicitly allows</li>
<li>Revocation: Quick ways to cancel or change agent access</li>
</ul>
<h2>2.2 Delegation and Trust</h2>
<ul>
<li>Agent ↔ Agent interactions: Delegation can magnify complexity if credentials are passed incorrectly</li>
<li>Human ↔ Agent interactions: The user's preferences and instructions must be respected</li>
<li>Agent ↔ API interactions: How services detect, block, or accommodate agent traffic</li>
</ul>
<h2>2.3 Potential Harms and Abuse</h2>
<ul>
<li>Automated scale: Creating 1,000 accounts to bypass rate limits or do large-scale scraping</li>
<li>Over-access: An agent that obtains more privileges than intended (e.g., unlimited spending)</li>
<li>User confusion: Complex credential or multi-factor flows can create friction and misconfiguration</li>
</ul>
<h1>3. Strategic Framework</h1>
<p>First we went over a possible implementation by Tobin of Authenticated Delegation. Basically, it extends existing authentication standards to handle AI agents:</p>
<h2>3. Technical Framework (Authenticated Delegation)</h2>
<h2>3.0.1 Extending OAuth 2.0 / OpenID Connect</h2>
<ul>
<li>User's ID-Token: Identifies the human user</li>
<li>Agent-ID Token: Identifies the AI system (capabilities, limitations)</li>
<li>Delegation Token: Grants the AI agent scoped authority on the user's behalf (spending limits, resource permissions, etc.)</li>
<li>Services verify these tokens via a trusted identity provider or using W3C Verifiable Credentials</li>
</ul>
<h2>3.0.2 Scoping and Permissions</h2>
<ul>
<li>Resource-Based Scopes: Precisely define what files, APIs, or data an agent can access</li>
<li>Task-Based or Natural Language Scopes: Higher-level instructions that must eventually map onto machine-readable rules</li>
<li>Audit &#x26; Revocation: Logs to track agent actions; users or platforms can revoke tokens when misuse is detected</li>
</ul>
<h2>3.0.3 Alternative Approaches</h2>
<ul>
<li>W3C Verifiable Credentials: More privacy-friendly, can avoid constant reliance on large identity providers</li>
<li>User-Managed Access (UMA): Centralizes policy management so users can set or adjust agent permissions in one place</li>
</ul>
<h2>3.1 Layers of Authorization</h2>
<ol>
<li>Session Layer
<ul>
<li>Similar to short-lived cookies or tokens that expire or can be invalidated promptly</li>
</ul>
</li>
<li>Persistent Identity Layer
<ul>
<li>Longer-lived tokens (OAuth style) with an audit log</li>
</ul>
</li>
<li>Delegation Layer
<ul>
<li>The user sets the scope: e.g., "Buy up to $50 in groceries," "Read messages but not send"</li>
</ul>
</li>
</ol>
<h2>3.2 Verification and Governance</h2>
<ul>
<li>KYC for Agents: Sites may want to know which human or entity controls a given agent</li>
<li>Consent and Alignment: Agents should reflect user intent and preferences rather than hidden agendas</li>
<li>Revocability: A user can quickly see all their agents and disable access if needed</li>
</ul>
<h2>3.3 Interoperability vs. Blocking</h2>
<ul>
<li>Agent-friendly APIs: Some services provide tailored endpoints or "agent modes"</li>
<li>Agent-blocking: Others may detect and prohibit "bot" behavior if it undermines site rules</li>
<li>Negotiation: Over time, standards may emerge for "trusted" agent tokens</li>
</ul>
<h1>4. Concrete Example: Budget.com</h1>
<p>Suppose Budget.com is an e-commerce platform focusing on low-cost goods or discount deals. Here's how it could play nicely with AI agents while still protecting user data and site integrity:</p>
<h2>Agent Registration</h2>
<ul>
<li>Agent Identity: Budget.com implements an "Agent Registration Portal." Whenever an agent wants to automate user tasks (e.g., shopping for deals), it must present some identifying info (e.g., "I'm an agent for user JaneDoe")</li>
<li>User Confirmation: The user receives a notification from Budget.com: "Is this your authorized agent? If so, grant it access"</li>
</ul>
<h2>Granular OAuth-Like Scopes</h2>
<ul>
<li>Basic Scopes: Read-only product listings, view discounted deals, or retrieve a user's wish list</li>
<li>Transaction Scopes: Purchasing privileges limited to a daily or weekly spending cap (e.g., "Agent can spend up to $50 per week")</li>
<li>Shipping and Billing: Agents can be disallowed from modifying the shipping address or saving a new credit card unless explicitly granted</li>
</ul>
<h2>Agent-Friendly Endpoints</h2>
<ul>
<li>API for Agents: Budget.com could offer a simplified JSON-based API for searching products, applying coupons, and checking out. This API can handle hundreds of quick queries without triggering typical bot-detection systems</li>
<li>No "Friction" for Agents: Because the agent is registered and known, Budget.com can skip certain captchas or speed bumps used to thwart unknown bots</li>
</ul>
<h2>Rate Limiting &#x26; Monitoring</h2>
<ul>
<li>Transaction Frequency Limits: If an agent suddenly tries thousands of transactions, Budget.com flags it</li>
<li>Behavior Monitoring: If the agent's pattern shifts suspiciously—e.g., scraping or bulk-reselling items—Budget.com can suspend that agent's access or require re-verification</li>
</ul>
<h2>User Dashboard</h2>
<ul>
<li>Agent Control Panel: Budget.com provides a user dashboard listing all agents authorized to shop on their behalf, showing each agent's last purchases, total spending, and active scopes</li>
<li>Instant Revocation: A single click lets the user suspend or remove an agent if it misbehaves or is no longer needed</li>
</ul>
<h2>Liability and Refunds</h2>
<ul>
<li>Clear Policy: Budget.com clarifies that any purchases made by the authorized agent are the user's responsibility unless it clearly violates site policy (e.g., an agent exploiting a bug)</li>
<li>Refund Mechanisms: Streamlined refunds if the agent over-purchases or picks the wrong items</li>
</ul>
<p>By implementing these measures, Budget.com:</p>
<ul>
<li>Increases trust with users who want to automate shopping tasks</li>
<li>Protects itself from unknown bots that might scrape data, spam the platform, or drive up costs</li>
<li>Offers a consistent user experience by letting AI agents handle the mundane steps (like searching for the best deals or filling out checkout forms) while giving humans final oversight</li>
</ul>
<h1>5. Proposed Approaches and Recommendations</h1>
<h2>Granular OAuth Scopes for Agents</h2>
<ul>
<li>Extend existing OAuth approaches so they fit specialized agent tasks (e.g., read-only wish lists, limited spending)</li>
<li>Maintain audit logs to track agent activity</li>
</ul>
<h2>Agent Identity Registry</h2>
<ul>
<li>A centralized place or service where platforms like Budget.com can confirm that a given agent truly represents a specific user</li>
<li>Could integrate trust scores or verified endorsements (e.g., agent is "legit" per industry standards)</li>
</ul>
<h2>Tiered Permissions and Rate Limits</h2>
<ul>
<li>Limit new or untested agents to small actions</li>
<li>Gradually scale privileges if usage stays within normal bounds</li>
</ul>
<h2>User-Centric Control Dashboards</h2>
<ul>
<li>Provide a one-stop location for each user to manage all authorized agents, set or modify scopes, and revoke access if the agent overreaches</li>
</ul>
<h2>Standardized Site Responses to Agents</h2>
<ul>
<li>Sites can either cooperate (offering dedicated agent APIs and streamlined flows) or block suspicious or unregistered agents</li>
</ul>
<h1>6. Conclusion</h1>
<p>In a future dominated by AI-driven automation, platforms like Budget.com can "play nice" with authorized agents by:</p>
<ul>
<li>Implementing agent registration with clear identity and permission scoping</li>
<li>Offering agent-friendly APIs that deliver content in an efficient, frictionless manner while still monitoring usage</li>
<li>Providing a robust user dashboard for oversight, quick revocation, and clear transaction logs</li>
